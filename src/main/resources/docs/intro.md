# Начало работы

Перед тем как начать работу с приложением его требуется настроить

При первом запуске TestRecorder будут созданы папки и файлы для конфигурации по след путям:

- Для Windows → C:\Users\<User>\AppData\Roaming\TestRecorder или C:\Users\<User>\TestRecorder при отсутствии AppData
- Для Linux → /home/<user>/.TestRecorder
- Для MacOs → ~/Library/Application Support/TestRecorder

## Для работы приложения понадобятся:
- chromedriver версии ващего chrome browser
- .jks файл с сертификатами для работы backend запросов

## Установка WebDriver (Chrome)
Скачиваем нужную нам версию веб драйвера - https://googlechromelabs.github.io/chrome-for-testing/ 
Для Windows - chromedriver, для MacOs - chrome, потребуется Google Chrome for Testing.app

### Возможные ошибки при запуске драйвера
Иногда веб-драйвер не запускается. Это происходит из-за конфликта версии вашего хрома и драйвера. Есть два варианта решения данной проблемы:

- Вариант первый - установите новую версию хрома прямо со страницы Chrome for Testing (chrome) (предпочтительный)
- Вариант второй - скопируйте ссылку для скачивания драйвера, в нее подставьте версию вашего хрома, которую можно найти в информации о браузере

## Пропишите все нужные пути

- Заполните путь до chromedriver или до Google Chrome for Testing.app в поле "ChromeDriver Path"
- Заполните путь до вашего .jks файла в поле "TrustStore"
- Введите пароль от вашего .jks в поле "Password"
- Введите "тип" вашего truststore в поле "Type". Если используете .jks, оставьте его без изменений

## Настройка доменов
Для корректной работы TestRecorder с бекенд запросами и для удобства переключения между стендами, требуется настроить домены.

Чтобы сделать это, надо зайти в "Меню" → "Настройки" → Вкладка "Домены". Введите домен и нажмите "Добавить". Таким образом у вас подтянутся сертификаты для данного домена и появится возможность переключать домен с помощью выпадашки на главном экране приложения.
