# Нюансы при работе с TestRecorder
## Работа с разными вкладками
> _Драйвер поддерживает работу только с 1 вкладкой_

Это ограничение связано именно с драйвером, а не приложением!
Пока вы записываете действия в браузере, активная вкладка будет переключаться автоматически, однако при самостоятельной настройке теста будте внимательны в данном вопросе

## Первый вызов backend запроса без получения токена через backend
> _Токен для backend запроса берется из cookie в открытом браузере_

Из-за данной особенности реализации (аккуратнее и удобнее пока не реализовали), после авторизации на платформе требуется использовать waitLoadingPage, чтобы токен точно появился в куках и приложение смогло его подхватить

## Перестались записываться действия в браузере
> _Бывет такое, что скрипты, которые "вставляются" в ваш браузер не успевают встроиться при обновлении страницы_

Это достаточно редко встречается, но бывает такое, что скрипты тест рекордера не успели нормально отработать и, соотвественно, нормально перестроится под обновленную страницу.
Чтобы исправить эту ситуацию, просто остановите и начните запись заново.
Для захвата "проблемной" кнопки, просто используйте поиск по селектору. Все нормально отработает при запуске теста

## Ошибки при backend запросах от TestRecorder
> _Вполне вероятно, у вас протухли сертификаты_

Для того, чтобы добавить актуальные серты в свой .jks файлик, достаточно просто удалить домен из списка и заново его подставить. Так подтянутся актуальные серты.
